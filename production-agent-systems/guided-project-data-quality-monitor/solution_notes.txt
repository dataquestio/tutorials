WHAT TO DO

Guided project. The root is lesson 4's solution plus test_solution.py. Learners build the
monitor themselves; solution-files/ holds the reference:

- dq_monitor.py
  - profile_day tool (registered into tools.TOOLS): file exists, row count vs trailing 7-day mean,
    content hash vs previous day, column changes, depth median, out-of-range values (mag or a
    renamed magnitude column, latitude, longitude), cross-network near duplicates (different net,
    within 5 s and 0.1 degrees). Profiles are saved to state/profiles.jsonl.
  - run_dq_day / run_dq_range: the lesson 1 outer loop with a data quality task and DQ_POLICY.
  - score(flags, planted, days): matches flags to the answer key by kind and day, plus event id
    for row-level issues. Returns recall, precision, missed ids, false positives, by_type.
  - report(...): task completion, tool usage efficiency, safety checks, detection.
- skills/data-quality-checks/SKILL.md: maps each profile signal to a flag kind.

Brief learners on the contract test_solution.py relies on: Section 7 names, runner.run_day, and
dq_monitor.score(flags, planted, days) returning planted_issues, issues_found, recall, precision.
Flag kinds must be the answer key's `type` values.

Run the monitor:

  cd solution-files
  python dq_monitor.py run --data-dir /workspace/data/usgs_gp --start 2026-06-01 --end 2026-08-31
  python dq_monitor.py report --data-dir /workspace/data/usgs_gp   # report again without rerunning

Check a solution (no key, no network, about 0.2 s):

  python test_solution.py --data-dir /workspace/data/usgs_gp

The perfect score comes from a profile tool that computes every signal and a skill that maps
signals to kinds one to one; the model mostly relays. Learners whose tools leave more judgment to
the model should expect lower recall. That gap is a good debrief topic.
