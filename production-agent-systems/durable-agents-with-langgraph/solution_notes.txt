WHAT TO DO

The lesson adds graph_agent.py: the same monitor as a LangGraph StateGraph with a SQLite
checkpointer (langgraph 1.2.12, langgraph-checkpoint-sqlite 3.1.1; added to requirements.txt in
this lesson). No langchain imports: messages are stored as plain Chat Completions dicts.

- Nodes: model -> approval -> tools -> model, END when the model answers without tools, or on
  max_steps / max_tokens_total.
- approval uses interrupt() for "ask" tools. Teach why tools run in a separate node: on resume
  LangGraph reruns the interrupted node from the top, so nothing before interrupt() may have
  side effects.
- One thread per day (thread_id "day-YYYY-MM-DD"). A paused day goes into pending_approvals with
  its thread_id and the run moves on; `approve --day D --decision yes|no` resumes that thread.
- The file-based state.json from lesson 1 is reused for the day-level bookkeeping; the
  checkpointer handles mid-day progress.

Side-by-side for the comparison screen:

| | File-based runner (L1) | LangGraph (L2) |
|---|---|---|
| Unit of recovery | Whole day | Last finished node |
| After a mid-day kill | Day reruns from scratch; tools must be idempotent | Continues before the next node |
| Human approval | Queued, not executed; needs a separate replay to act on it | Thread pauses; approve resumes it and the tool runs |
| Extra pieces | None (json + os.replace) | langgraph, sqlite file, plain-dict message state |
| What you write yourself | Commit logic, idempotent tools | Graph wiring, interrupt rules |


ASSUMPTIONS

- Data /workspace/data/usgs. Model gpt-6-luna, reasoning_effort "none".
- Compaction (memory.py) is deliberately not wired into the graph.
  Every simulated day starts with a fresh context and days run at about 6k to 16k tokens,
  far below compact_at_tokens. Adding it would need extra graph state and a summary node,
  which pulls the lesson away from checkpoints and resume. Compaction is taught in Course 1
  lesson 2 and lives in this course's agent.py. The lesson should say in one line that
  reusing graph_agent.py for long single-day tasks means adding compaction.
- More than one "ask" call in a single model turn is handled: each resume answers one
  interrupt, and approve_command re-queues the next one (see EXPECTED RESULT).
