WHAT TO DO

Learners point the lesson 4 agent at a new dataset (dohmh/inspections.csv),
write at least one skill for it, and answer questions.txt. The root has the
lesson 4 code, its two 311 skills, questions.txt, and test_solution.py.

Reference solution in solution-files/:
- skills/restaurant-inspections/SKILL.md replaces the two 311 skills, which
  would mislead the agent on this data (different statuses, date formats,
  boroughs).
- run_questions.py answers every question in one shared workspace and writes
  answers.md.
- test_solution.py and questions.txt, identical to the root.

This is the one place a solution removes files its root had (the 311 skills).
The spec's "solution MUST NOT remove anything" rule needs a GP exception.

Commands (run from solution-files/):
  python test_solution.py --data-dir <dohmh>
  python run_questions.py --data-dir <dohmh> --output answers.md


ASSUMPTIONS

- Data quirks the skill covers: one row per violation (inspection key is CAMIS +
  INSPECTION DATE + INSPECTION TYPE); 01/01/1900 placeholder date for 3,830
  never-inspected restaurants; BORO "0" on 344 rows; grades N/Z/P pending; SCORE
  repeats on every violation row; lower score is better.
- test_solution.py checks harness behaviour only. It also passes on the root
  before the learner changes anything, because the root already has working
  lesson 4 code and the 311 skills. Learner work is judged by the answers.
