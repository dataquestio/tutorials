WHAT TO DO

Start from demo_tool_loop.py: the lesson 1046 loop with one hand-written tool
(count_requests_by_borough). Show it answering the question its tool was built
for, then fail on anything else (e.g. median closing time by borough).

Then build solution-files/: general tools (tools.py), the loop with explicit
stop reasons and token accounting (agent.py), the JSONL trace (tracing.py), and
the CLI (run.py). The system prompt's "How to work" steps are where
verification lives: explore, analyze with printed summaries, fix errors, check
plausibility, answer with what was checked.

Commands (run from solution-files/):
  python run.py --data-dir <nyc311> --question "Which borough's residential noise complaints took longest to close, by median hours, in summer 2026?"
  python run.py --data-dir <nyc311> --question "Make a chart of daily fireworks complaints from June 15 to July 15, 2026 and save it as fireworks.png. On which day did they peak?"


ASSUMPTIONS

- Model gpt-6-luna on Chat Completions with reasoning_effort="none". With
  reasoning on, the API rejects tools (HTTP 400).
- The nyc311 dataset folder holds only the three CSV files. No README: the
  agent has to discover formats itself.
- run.py links the data folder into the workspace as data/. File tools check
  containment without resolving symlinks, so data/ works and ../ doesn't.
- No truncation yet. read_file returns at most max_lines (default 50) lines, and
  the prompt tells the model to print summaries. Truncation is lesson 2.
- Subprocesses still see OPENAI_API_KEY. Stripping it is lesson 4.
